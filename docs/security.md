# Безопасность

Модель угроз: клиент присылает произвольный файл и произвольные параметры
конвертации. Всё, что делает сервис дальше, не должно давать возможности
прочитать чужие данные, выполнить код на хосте или исчерпать его ресурсы.

## Слои проверки запроса

Порядок прохождения: `ограничитель частоты` → `разбор multipart` →
`схема параметров` → `расширение и сигнатура` → `zip-гард` →
`вид документа OOXML` → `очередь`.

Что отсекается до обращения к инфраструктуре — проверяется тестами
(`tests/api.test.js`), потому что именно этот рубеж защищает хранилище
и очередь от мусора.

| Слой | Что делает | Где |
|---|---|---|
| Ограничитель частоты | Ведро с токенами на IP: `RATE_BURST` ёмкость, `RATE_PER_SEC` пополнение | `apps/api/src/common/rate-limit.guard.ts` |
| Лимит размера | `MAX_FILE_BYTES` (100 МиБ) на уровне multer и в сервисе | `apps/api/src/conversion/conversion.controller.ts` |
| Схема параметров | zod: диапазоны, перечисления, длины | `packages/contract/src/schemas.ts` |
| Расширение и сигнатура | Расширение вне списка отвергается, PK-заголовок подтверждает zip | `apps/api/src/security/magicBytes.ts` |
| Zip-гард | Бомбы, path traversal, дубликаты записей, число записей, макросы | `apps/api/src/security/zipGuard.ts` |
| Вид документа | `xl/workbook.xml` или `word/document.xml`; расхождение с расширением — отказ | `apps/api/src/security/ooxml.ts` |

Zip-гард важен именно потому, что входные форматы — zip: и книгу, и документ
распаковывает LibreOffice, и делать это на архиве с соотношением сжатия
1000:1 поздно — процесс съест память раньше, чем вернёт ошибку.

Различать XLSX и DOCX по сигнатуре нельзя: она у них одна и та же. Вид
документа определяется по главной части пакета, поэтому проверка идёт после
zip-гарда — разбирать оглавление контейнера, не прошедшего проверку, незачем.

Документы с макросами отсекаются по части пакета `vbaProject.bin`:
расширения `.xlsm` и `.docm` сервис не принимает, но по структуре контейнера
они не отличаются от обычных, и без этой проверки макросодержащий файл
дошёл бы до LibreOffice. Дополнительно при загрузке документа выставлен
`MacroExecutionMode = NEVER_EXECUTE`.

## Изоляция конвертации

Конвертация выполняется в отдельном контейнере, а не в процессе API:

- `uno-worker` не имеет доступа ни к HTTP-порту API, ни к учётным данным
  хранилища сверх своего бакета;
- контейнер запускается с `cap_drop: ALL`, `no-new-privileges: true`,
  `read_only: true` (запись только в `tmpfs` `/tmp`), non-root пользователем
  и `pids_limit`;
- UNO-бридж слушает **только loopback**: у UNO нет аутентификации,
  и выставленный наружу порт означал бы возможность выполнить произвольный
  макрос в чужом процессе;
- внешние ссылки в документе не обновляются (`UpdateLinks: 0`), поэтому
  он не может заставить сервис сходить в сеть;
- макросы документа не исполняются: `MacroExecutionMode = NEVER_EXECUTE`
  при загрузке, плюс сам файл с проектом VBA не проходит zip-гард.

## Проверка результата

Воркер проверяет размер полученного PDF (`MIN_OUTPUT_BYTES`) до загрузки
в хранилище: формально успешное завершение скрипта ещё не означает, что
экспорт дал документ. Файл меньше 32 байт — это не PDF, и задача помечается
упавшей, а не отдаётся клиенту.

## Обработка ошибок

Формат ответа единый: `{ error, message, jobId?, requestId? }`, где `error` —
код в snake_case из контракта. Всё, что не является `AppError`, отдаётся
как 500 с общим текстом: иначе в ответ попадали бы `err.message`
и системные коды вроде `ENOENT`, раскрывая внутреннее устройство сервиса.

В сообщениях об ошибках конвертации остаётся текст от LibreOffice — он
относится к документу клиента и полезен для разбора, но не содержит путей
на хосте (скрипт работает с путями внутри контейнера и `/tmp`).

## Что ослаблено осознанно

**Autoscaler монтирует `/var/run/docker.sock`** — это root-эквивалент
на хосте: через Docker API можно создать привилегированный контейнер
с корневой ФС хоста. Компенсирующие меры: сервису не передаются данные
клиентов, он не принимает внешних запросов, а его собственный клиент умеет
только четыре операции (перечислить, создать, запустить, удалить).
В Kubernetes эта роль передаётся KEDA, и сокет монтировать не нужно.

**Порт API опубликован только на loopback.** При `TRUST_PROXY=1` клиент,
дотянувшийся до порта напрямую, подставил бы в `X-Forwarded-For` чужой адрес
и обошёл ограничитель частоты. Наружу API отдаёт nginx.

**Учётные данные MinIO по умолчанию — `minioadmin`.** Это значение годится
только для локального запуска; в продакшене задайте `S3_ACCESS_KEY`
и `S3_SECRET_KEY` и не публикуйте порт MinIO наружу без необходимости.

## Ограничения модели

- **Файлы не проверяются антивирусом.** Сервис проверяет структуру контейнера
  и лимиты, но не содержимое документа.
- **Пароль защищённой книги не поддерживается.** Параметры `userPassword`
  и `ownerPassword` относятся к PDF на выходе; зашифрованная книга упадёт
  с `conversion_failed`.
- **Результаты не удаляются автоматически.** PDF лежит в хранилище до
  истечения политики жизненного цикла бакета; ссылка живёт час, но сам
  объект — дольше. Настройте lifecycle-политику MinIO под свои требования.
- **Аутентификации API нет.** Сервис рассчитан на работу во внутреннем
  контуре; наружу его следует выставлять вместе с аутентификацией на прокси.
