# Конфигурация

Источник истины по значениям и их обоснованиям — `packages/config/src/index.ts`.
`.env.example` перечисляет то, что имеет смысл менять при развёртывании.

## Где читается окружение

| Слой | Файл | Когда читается |
|---|---|---|
| Домен (очередь, хранилище, воркер, autoscaler) | `packages/config/src/index.ts` | При импорте модуля |
| NestJS-слой (порт, логгер, ограничитель) | `apps/api/src/env.ts` | При создании приложения |

Разница в моменте чтения важна для тестов: они выставляют `RATE_*`
в `beforeAll`, то есть уже после импорта модулей, и при чтении на уровне
модуля настройка терялась бы.

## Основные переменные

### Хранилище и очередь

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `REDIS_HOST`, `REDIS_PORT` | `valkey`, `6379` | Valkey: очередь BullMQ и состояние задач |
| `S3_ENDPOINT`, `S3_PORT` | `minio`, `9000` | Адрес хранилища для операций |
| `S3_PUBLIC_ENDPOINT`, `S3_PUBLIC_PORT` | равны внутренним | Адрес, который попадёт в presigned-ссылку |
| `S3_BUCKET` | `conversions` | Бакет входных файлов и результатов |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | `minioadmin` | Учётные данные |
| `S3_USE_SSL`, `S3_PUBLIC_USE_SSL` | `false` | TLS при обращении к хранилищу |

**`S3_PUBLIC_ENDPOINT` — частая причина «ссылка не открывается».** Подпись
presigned URL включает хост: ссылка, подписанная для внутреннего имени
(`minio:9000`), снаружи не работает, потому что браузер такого имени не знает.

### Лимиты и таймауты

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_FILE_BYTES` | 100 МиБ | Потолок размера входного файла |
| `MIN_OUTPUT_BYTES` | 32 | Минимальный осмысленный размер PDF |
| `CONVERSION_TIMEOUT_MS` | 120000 | Таймаут одной конвертации (для тяжёлой очереди в compose — 300000) |
| `UNO_CONNECT_TIMEOUT_MS` | 30000 | Ожидание готовности UNO-бриджа |
| `PRESIGN_EXPIRY_SEC` | 3600 | Время жизни ссылки на результат |
| `JOB_TTL_SEC` | 86400 | Время жизни записи о задаче |

### Очереди и сложность

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `QUEUE_PREFIX` | `xlsx2pdf` | Базовое имя очередей: `<prefix>.<tier>` |
| `WORKER_QUEUE` | `light` | Очередь, которую слушает воркер |
| `COMPLEXITY_LIGHT_MAX_BYTES` | 2 МиБ | Порог лёгкой задачи по размеру |
| `COMPLEXITY_LIGHT_MAX_SHEETS` | 3 | Порог лёгкой задачи по листам книги |
| `COMPLEXITY_LIGHT_MAX_PAGES` | 5 | Порог лёгкой задачи по страницам документа |
| `COMPLEXITY_MEDIUM_MAX_BYTES` | 20 МиБ | Порог средней задачи по размеру |
| `COMPLEXITY_MEDIUM_MAX_SHEETS` | 20 | Порог средней задачи по листам книги |
| `COMPLEXITY_MEDIUM_MAX_PAGES` | 30 | Порог средней задачи по страницам документа |

Уровень берётся по **старшему** из признаков. Листы читаются из книги,
страницы — из свойств документа (`docProps/app.xml`), поэтому для книги
действуют только пороги по листам, для документа Word — только по страницам.
`QUEUE_PREFIX` влияет
на ключи Redis, которые читают KEDA и autoscaler: при смене префикса
манифесты `deploy/k8s/scaledobject-*.yaml` нужно поправить.

### UNO

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `UNO_HOST`, `UNO_PORT` | `127.0.0.1`, `2002` | Адрес бриджа (только loopback) |
| `UNO_SCRIPT_PATH` | `/app/docker/uno/uno_convert.py` | Путь к скрипту конвертации |
| `PYTHON_BIN` | `python3` | Интерпретатор с модулем `uno` |

### BullMQ

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BULLMQ_LOCK_DURATION` | `CONVERSION_TIMEOUT_MS × 2` | Блокировка задачи воркером |
| `BULLMQ_STALLED_INTERVAL` | `CONVERSION_TIMEOUT_MS` | Как часто искать зависшие задачи |
| `BULLMQ_MAX_STALLED_COUNT` | 1 | Сколько раз задача может быть переобработана |
| `JOB_ATTEMPTS` | 1 | Повторы при ошибке конвертации |
| `FAILED_JOB_TTL_SEC`, `MAX_FAILED_JOBS` | 86400, 1000 | Ограничение памяти под упавшие задачи |

### Ограничитель частоты

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RATE_PER_SEC` | 5 | Устойчивая скорость запросов на IP |
| `RATE_BURST` | 20 | Предельный всплеск |
| `TRUST_PROXY` | `false` | Доверять `X-Forwarded-For` |

Ведро ограничителя живёт в памяти процесса. Без `TRUST_PROXY=1` за nginx
`req.ip` у всех клиентов равен адресу контейнера nginx, и все они делят одно
ведро. В compose значение равно `1`, а порт API опубликован только
на loopback — иначе клиент подставил бы в заголовок чужой адрес.

### Автомасштабирование

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DOCKER_SOCKET_PATH` | `/var/run/docker.sock` | Сокет Docker API |
| `AUTOSCALER_WORKER_IMAGE` | `doc-converter-uno-worker:latest` | Образ реплик |
| `AUTOSCALER_NETWORK` | `doc-converter_converter` | Сеть, к которой подключаются реплики |
| `AUTOSCALER_POLL_INTERVAL_MS` | 15000 | Период опроса очередей |
| `AUTOSCALER_MAX_STEP` | 1 | Предельный шаг изменения реплик за цикл |
| `WORKER_MEMORY_LIMIT_MB` | 2048 | Предел памяти контейнера-реплики |

Профили по уровням (min/max/`jobsPerReplica`/cooldown) заданы в
`SCALING_PROFILES` (`packages/config/src/index.ts`) — там же их обоснование.

## Проверки на старте

Отдельной валидации конфигурации в домене нет: числовые переменные читаются
как есть, и некорректное значение проявляется при первом обращении. Явно
проверяется только окружение NestJS-слоя (`parseEnv`, zod-схема) — при
некорректном значении приложение падает на старте с перечнем проблем.

Практическое следствие: опечатка в переменной домена (например,
`CONVERSION_TIMEOUT_MS=12o000`) даст `NaN` и таймаут, который не срабатывает.
При разборе странного поведения проверяйте значения переменных, а не только
код.
